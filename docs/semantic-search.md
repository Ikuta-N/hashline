# 意味検索

文字ではなく意味でノートを引く。任意機能であり、これを入れなくても
アプリはインストールでき、起動し、意味検索以外はすべて動く。

```bash
uv sync --extra ml            # torch（CPU ビルド）と sentence-transformers
uv run hashline index         # 未埋め込みのノートを埋め込む
uv run hashline search 眠れない --semantic
```

```
0.0164      5  2026-08-09 22:45  昨日は寝不足で頭が回らなかった #日記  [日記]
0.0161      3  2026-08-09 22:45  朝の散歩を習慣にしたい #日記          [日記]
```

どちらのノートにも「眠れない」という文字列は無いので、`--semantic` を
付けない `hashline search 眠れない` は何も見つけない。

Web UI では検索ボックス横の **semantic** チェックボックスがこれにあたり、
事前に走らせるものは無い。サーバは起動時と **ノートを書くたびに**、
未埋め込みのものをバックグラウンドスレッドで埋め込む。ブラウザで取った
ノートは再起動なしに意味検索の対象になる。パスは同時に 1 本だけ走り、
残りが無くなるまで見続けるので、一括インポートでノートごとにスレッドが
立つことはない。`HASHLINE_NO_INDEX=1` で切ると、画面は「インデックス中」
と偽らずに *未インデックス* と表示する。エクストラが入っていない場合は、
トグルが黙って空の結果を返すのではなく、その旨を表示する。

`hashline index` は `notes_without_embedding` をたどるので、再実行しても
コストはかからない。`--rebuild` で全件を埋め込み直し、`--limit` で途中で
止める。前回のインデックス以降に追加されたノートがある検索は、短い結果
リストだけを手掛かりに残すのではなく、何件が未処理かを表示する。

## 2 つのランキングをどう混ぜるか

BM25 とコサイン類似度は無関係な尺度なので、スコアではなく **順位** を
融合する。各リストがノートごとに `1 / (60 + rank)` を出す（reciprocal
rank fusion）。調整すべき正規化定数が無く、3 つ目のランカーを足すときも
既存の 2 つを見直さずに済む。両者は `--limit` によらず上位 100 件ずつを
出すので、両方のランカーが 25 位に置いたノートが、片方だけが 20 位に
置いたノートに負けることはない。

## ベクトルの保存形式

`embeddings` テーブルは最初のリリースからスキーマにあるため、この機能の
追加にあたって移行も再インポートも要らなかった。

- リトルエンディアンの `float32` を明示的に固定しているので、`.db`
  ファイルはマシン間で持ち運べる。
- `dim` は BLOB 内のヘッダではなく独立した列に置く。
- ベクトルは書き込み時に L2 正規化する。
- `embeddings.model` にはモデル名だけでなくプレフィックスの規約
  （`intfloat/multilingual-e5-small+query`）を記録する。e5-small は
  置き換え前の MiniLM 系モデルと同じ 384 次元なので、次元数の検査では
  両者の取り違えを検出できない。

このプレフィックスは e5 のものである。ノート側も検索クエリ側も
`query: ` を付けて埋め込む。ある語句と同じ意味のノートを探すことは
対称な課題だからである。

## どのコードが何を読み込むか

- `ml/search.py` は純粋な numpy で、モデルランタイムを一切 import しない。
- `ml/embed.py` はバックエンドを関数の内側で import する。
- `ml/protocols.py` は両者が共有する `Embedder` プロトコルを定義する。
- `ml/hybrid.py` はストアからベクトルを読み出し、2 つのランキングを融合
  する。CLI と Web の双方がこれを呼ぶので、検索ロジックの写しをどちらの
  アダプタも持たない。
- 両アダプタとも、これらを必要な関数の内側で import する。したがって
  起動時に numpy のコストを払うことはない。
